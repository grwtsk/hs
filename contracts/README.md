# Editorial contracts and phase boundary

[Author instructions](author-instructions.json) record operative direction and
source chronology, with agent summaries explicitly attributed. They are not human
approval of future prose. [Source evidence](../research/source-evidence.json),
[agent proposals](../decisions/agent-proposals.json),
[human dispositions](../decisions/human-dispositions.json), and
[disagreements](../research/disagreements.yaml) remain separate.

The [phase record](phase.json) admits manuscript-only work now. G1 #36 accepts the
exact complete manuscript and contracts; G2 #38 authorizes defined production
implementation; G3 #61 authorizes exact release actions. Preparing any gate packet
cannot depend on that packet already being approved. No actual gate is accepted.

The records in this slice are an editorial implementation, not adoption of the
agent's four-record runtime proposal. A well-formed declared human record is not
independently authenticated consent. Source/approval identities can become stale.
For external issue sources without captured exact bytes, this slice deliberately
refuses approval binding; a later source-reading slice must pin those bytes first.

The #82 demonstrator is an isolated author-carried experiment, not production G2
or permission to add runtime code here. The checker distinguishes proposed work,
provisional prose, reviewable records, acceptance and release. Its filename scan
is defense in depth, not proof that no interface behavior can exist in a file.
